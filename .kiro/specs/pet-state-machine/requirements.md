# Pet State Machine — Requirements

## Introduction

The pet state machine is the heart of Haunted Pet To-Do. It defines every life stage a ghost pet passes through (egg → hatchling → adult forms → dead → tombstone), the stats that govern its health, and the events that drive transitions. All logic is pure and injectable-clock-compatible so it can be tested deterministically and fast-forwarded for demos.

This spec covers: life stages and transitions, stat bounds (HP, hunger, mood), streak tracking, evolution rules (including the four evolved adult forms determined by time-of-day and task category), death, tombstone display, rebirth with graveyard history, and the central `applyPetEvent` reducer API.

## Glossary

| Term | Definition |
|---|---|
| **PetStage** | The visual/behavioral phase of the pet: `egg`, `hatchling`, `adult`, `adult_night_owl`, `adult_early_bird`, `adult_scholar`, `adult_haunter`. Does NOT include liveness states — those are `PetStatus`. |
| **PetStatus** | Liveness: `alive`, `dead`, or `tombstone`. Orthogonal to `PetStage`. |
| **HP** | Hit Points — the pet's primary survival stat, in `[0, MAX_HP]`. |
| **Hunger** | How fed the pet is, in `[0, 100]`. Higher = more fed. |
| **Mood** | Emotional state, in `[0, 100]`. Higher = happier. |
| **Streak** | Count of consecutive days on which at least one task was completed. |
| **Evolution** | Transition from `adult` to one of four evolved adult stages. |
| **Evolved Form** | One of `adult_night_owl`, `adult_early_bird`, `adult_scholar`, `adult_haunter`. |
| **Graveyard** | Append-only list of past `TombstoneRecord` entries kept in pet state. |
| **TombstoneRecord** | Snapshot of a dead pet's final stats and epitaph. |
| **Epitaph** | Short darkly-funny verse generated by the LLM (or a deterministic fallback). |
| **GameEvent** | A discriminated union describing things that happen to the pet or tasks. |
| **applyPetEvent** | Pure reducer: `(state: PetState, event: GameEvent, now: number) => PetState`. |
| **NagLevel** | `gentle`, `dramatic`, or `haunting` — controls AI nag intensity. |
| **MAX_HP** | Constant maximum hit points (defined in `constants.ts`). |
| **DECAY_RATE_HP** | HP lost per hour when no tasks are completed. |
| **EVOLUTION_HOUR_THRESHOLD** | Hours the pet must spend as `adult` before evolution is possible (24). |

## Requirements

### 1. Life Stages

**Requirement 1 — Egg stage**

_User Story_: As a user starting the app for the first time (or after a rebirth), I want my pet to begin as an egg so that the hatching feels like a fresh start.

**Acceptance Criteria**:

- 1.1: WHEN a new pet is created OR WHEN a rebirth event is applied, THEN the system SHALL set `PetState.stage` to `"egg"` and `PetState.status` to `"alive"`.
- 1.2: WHEN `PetState.stage` is `"egg"`, THEN the system SHALL NOT decay HP and SHALL NOT apply zombie damage. An overdue task left over from a previous life does not hurt a new egg.
- 1.3: WHEN `PetState.stage` is `"egg"`, THEN the system SHALL render `egg_idle.png` and SHALL NOT display stat bars.

**Requirement 2 — Hatchling stage**

_User Story_: As a user who completes their first task, I want my pet to hatch from the egg so that I feel rewarded for taking action.

**Acceptance Criteria**:

- 2.1: WHEN a `TASK_COMPLETED` event is applied AND `PetState.stage` is `"egg"`, THEN the system SHALL transition `PetState.stage` to `"hatchling"` and SHALL emit a `PET_HATCHED` event.
- 2.2: WHEN `PetState.stage` is `"hatchling"`, THEN the system SHALL display the `hatchling_idle.png` sprite and SHALL show all three stat bars.
- 2.3: WHILE `PetState.stage` is `"hatchling"`, the system SHALL apply normal stat decay each tick.

**Requirement 3 — Adult stage**

_User Story_: As a user who has completed enough tasks, I want my pet to grow into an adult so that I can see my progress reflected in the pet's appearance.

**Acceptance Criteria**:

- 3.1: WHEN `PetState.tasksCompletedTotal >= 7` AND `PetState.currentStreak >= 3` AND `PetState.stage` is `"hatchling"`, THEN the system SHALL transition `PetState.stage` to `"adult"` and SHALL emit a `PET_GREW_UP` event.
- 3.2: WHEN `PetState.stage` is `"adult"`, THEN the system SHALL display `adult_idle.png` (or `adult_hungry.png` when hunger < 30).
- 3.3: IF `PetState.stage` is `"adult"` and `PetState.hunger < 30`, THEN the system SHALL display the `adult_hungry.png` sprite.

**Requirement 4 — Four evolved adult forms**

_User Story_: As a user with a long completion streak, I want my pet to evolve into a unique form that reflects my productivity patterns so that the evolution feels personal and meaningful.

**Acceptance Criteria**:

- 4.1: WHEN `PetState.currentStreak >= 10` AND `PetState.stage` is `"adult"` AND `PetState.hoursAsAdult >= 24`, THEN the system SHALL be eligible to evolve.
- 4.2: WHEN evolution is triggered AND the majority of the last 10 completed tasks were completed between 22:00–05:59 local time, THEN the system SHALL set `PetState.stage` to `"adult_night_owl"`.
- 4.3: WHEN evolution is triggered AND the majority of the last 10 completed tasks were completed between 06:00–10:59 local time, THEN the system SHALL set `PetState.stage` to `"adult_early_bird"`. 05:00–05:59 counts as night owl only, so the two time-of-day forms do not share an hour.
- 4.4: WHEN evolution is triggered AND the majority of the last 10 completed tasks had `category = "study"` OR `category = "work"`, THEN the system SHALL set `PetState.stage` to `"adult_scholar"`.
- 4.5: WHEN evolution is triggered AND none of criteria 4.2–4.4 match (or the pattern is a tie, or there is no history), THEN the system SHALL set `PetState.stage` to `"adult_haunter"`. Majority means a strict majority: `floor(n / 2) + 1`. `n === 0` is haunter. A 5–5 split is not a majority.
- 4.6: WHEN `PetState.stage` changes to any evolved form, THEN the system SHALL emit a `PET_EVOLVED` event containing the new stage.
- 4.7: IF multiple evolution criteria are met simultaneously, THEN the system SHALL apply the first matching rule in priority order: `night_owl` > `early_bird` > `scholar` > `haunter`.

**Requirement 5 — Death**

_User Story_: As a user who has let all their tasks go overdue, I want my pet to die dramatically so that I understand the consequence and feel motivated to start fresh.

**Acceptance Criteria**:

- 5.1: WHEN a decay or zombie-drain event causes `PetState.hp` to reach `0`, THEN the system SHALL set `PetState.status` to `"dead"`. (`PetState.stage` is NOT changed — the visual stage is preserved so the tombstone can show which form the pet was in.)
- 5.2: WHEN `PetState.status` is `"dead"`, THEN the system SHALL NOT apply further HP decay, hunger decay, or zombie drain.
- 5.3: WHEN `PetState.status` is `"dead"`, THEN the system SHALL NOT allow stat increases from task completions.
- 5.4: WHEN `PetState.status` is `"dead"`, THEN the system SHALL emit a `PET_DIED` event containing the final stats snapshot.

**Requirement 6 — Tombstone**

_User Story_: As a user whose pet has died, I want to see a tombstone with a darkly funny epitaph so that the death feels meaningful and memorable.

**Acceptance Criteria**:

- 6.1: WHEN a `EPITAPH_READY` event is applied AND `PetState.status` is `"dead"`, THEN the system SHALL set `PetState.status` to `"tombstone"` and SHALL store the epitaph string in `PetState.currentEpitaph`.
- 6.2: IF the LLM epitaph call fails, THEN the system SHALL use the deterministic fallback: `"Here lies a to-do list. It never stood a chance."`.
- 6.3: WHEN `PetState.status` is `"tombstone"`, THEN the system SHALL NOT accept any gameplay events (decay, damage, task completion) until a `REBIRTH` event is applied.
- 6.4: WHEN `PetState.status` is `"tombstone"`, THEN the system SHALL display `tombstone.png` with the epitaph text overlaid.

**Requirement 7 — Rebirth and graveyard**

_User Story_: As a user who has dismissed the tombstone, I want a new egg to appear and my fallen pet's memory preserved in a graveyard so that the cycle begins again with history intact.

**Acceptance Criteria**:

- 7.1: WHEN a `REBIRTH` event is applied AND `PetState.status` is `"tombstone"`, THEN the system SHALL push a `TombstoneRecord` to `PetState.graveyard` before resetting pet state.
- 7.2: WHEN a `REBIRTH` event is applied, THEN the system SHALL create a new `PetState` with `stage = "egg"`, `status = "alive"`, `hp = MAX_HP`, `hunger = 100`, `mood = 100`, and `currentStreak = 0`.
- 7.3: WHEN a `REBIRTH` event is applied, THEN the system SHALL preserve `PetState.graveyard` from the previous pet.
- 7.4: WHEN `PetState.graveyard` has at least one entry, THEN the system SHALL make graveyard records accessible for display in the UI.

### 2. Stats

**Requirement 8 — HP bounds**

_User Story_: As a player, I want HP to always stay within safe numeric bounds so that the UI never renders negative bars or overflows.

**Acceptance Criteria**:

- 8.1: WHEN any event modifies `PetState.hp`, THEN the system SHALL clamp the result to `[0, MAX_HP]`.
- 8.2: IF `PetState.hp` would exceed `MAX_HP` after healing, THEN the system SHALL cap it at `MAX_HP`.

**Requirement 9 — Hunger bounds**

_User Story_: As a player, I want the hunger stat to accurately reflect feeding without exceeding logical limits.

**Acceptance Criteria**:

- 9.1: WHEN any event modifies `PetState.hunger`, THEN the system SHALL clamp the result to `[0, 100]`.

**Requirement 10 — Mood bounds**

_User Story_: As a player, I want mood to always be a valid percentage so it displays correctly on the stat bar.

**Acceptance Criteria**:

- 10.1: WHEN any event modifies `PetState.mood`, THEN the system SHALL clamp the result to `[0, 100]`.

### 3. Streak Tracking

**Requirement 11 — Streak increment**

_User Story_: As a user who completes tasks on consecutive days, I want my streak to increment so that I'm motivated to keep going.

**Acceptance Criteria**:

- 11.1: WHEN a `TASK_COMPLETED` event is applied AND the task was completed on a different calendar day than `PetState.lastCompletionDay`, THEN the system SHALL increment `PetState.currentStreak` by 1.
- 11.2: WHEN a `TASK_COMPLETED` event is applied AND the task was completed on the same calendar day as `PetState.lastCompletionDay`, THEN the system SHALL NOT change `PetState.currentStreak`.
- 11.3: WHEN a `TASK_COMPLETED` event is applied, THEN the system SHALL update `PetState.lastCompletionDay` to the calendar day of the event's `now` timestamp.

**Requirement 12 — Streak break**

_User Story_: As a user who misses a full day without completing any task, I want my streak to reset so that the streak has real stakes.

**Acceptance Criteria**:

- 12.1: WHEN a decay tick event is applied AND more than `STREAK_BREAK_HOURS` (48) hours have elapsed since `PetState.lastCompletionAt` with no completion, THEN the system SHALL set `PetState.currentStreak` to `0`.
- 12.2: WHEN `PetState.currentStreak` resets, THEN the system SHALL set `PetState.mood` to `max(0, PetState.mood - 20)`.

### 4. applyPetEvent Reducer

**Requirement 13 — Pure reducer API**

_User Story_: As a developer, I want all pet state changes to flow through a single pure reducer so that state transitions are testable, replayable, and clock-injectable.

**Acceptance Criteria**:

- 13.1: WHEN `applyPetEvent(state, event, now)` is called, THEN the system SHALL return `{ state, emitted }` without mutating the input. `emitted` holds consequence events (`PET_HATCHED`, `PET_GREW_UP`, `PET_EVOLVED`, `PET_DIED`, `STREAK_BROKEN`). The client does not decide evolution.
- 13.2: WHEN `applyPetEvent` is called with the same `state`, `event`, and `now`, THEN the system SHALL return an equal output (deterministic). Ids that would otherwise be random (`pet id`, `tombstoneId`) are inputs, not generated inside the reducer.
- 13.3: WHEN `applyPetEvent` is called, THEN the system SHALL NOT call `Date.now()` or `new Date()` internally.
- 13.4: WHEN `applyPetEvent` receives an unrecognized event type, THEN the system SHALL return `state` unchanged.
- 13.5: WHERE the pet status is `"tombstone"`, WHEN `applyPetEvent` is called with any event other than `REBIRTH` or `EPITAPH_READY`, THEN the system SHALL return `state` unchanged.
